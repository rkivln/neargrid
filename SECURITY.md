# Security Policy

NearGrid takes security and user privacy seriously. We appreciate the efforts of security researchers and community members who responsibly disclose vulnerabilities and help us keep the platform safe.

This document outlines the supported versions of NearGrid and the process for reporting security vulnerabilities.

## Supported Versions

Security updates are prioritized for the latest stable release.

| Version | Security Support |
|---|---|
| 1.0.x | Supported |
| Older versions | Not supported |

Users are encouraged to upgrade to the latest available release to receive security improvements and bug fixes.

## Reporting a Vulnerability

If you discover a security vulnerability in NearGrid, please report it responsibly.

**Preferred reporting method:**

1. Visit the [NearGrid GitHub Repository](https://github.com/rkivln/neargrid).
2. Navigate to the **Security** tab.
3. Select **Report a vulnerability** under Security Advisories, if private vulnerability reporting is enabled.
4. Provide a detailed description of the issue and steps to reproduce it.

If private vulnerability reporting is unavailable, contact the repository maintainer privately through GitHub before sharing technical details publicly.

### Information to Include

Please include the following information in your report:

- Description of the vulnerability.
- Affected application version.
- Steps to reproduce the issue.
- Potential security impact.
- Screenshots, logs, or proof-of-concept evidence, if applicable.
- Suggested mitigation, if known.

## Response Timeline

We aim to follow this responsible disclosure timeline:

| Activity | Target Timeline |
|---|---|
| Initial acknowledgment | Within 7 days |
| Initial assessment | Within 14 days |
| Progress updates | As appropriate |
| Security fix | Based on severity and complexity |

These are response targets, not guaranteed deadlines. Critical vulnerabilities will receive priority attention.

## Responsible Disclosure Guidelines

To protect NearGrid users and the wider community, security researchers are requested to:

- Avoid accessing, modifying, or exposing other users' private information.
- Do not perform destructive testing or disrupt production services.
- Do not exploit vulnerabilities beyond what is necessary to demonstrate the issue.
- Do not publicly disclose vulnerabilities before coordinating with the maintainer.
- Allow reasonable time for investigation and remediation.

## Security Areas

Security reports related to the following areas are particularly welcome:

- Authentication and authorization vulnerabilities.
- Firebase security rules and database access.
- Unauthorized access to community data.
- Location privacy and geospatial data exposure.
- QR code invitation and access-pass security.
- API and backend vulnerabilities.
- Data leakage and insecure storage.
- Application integrity and dependency vulnerabilities.

## Privacy Commitment

NearGrid is designed with a privacy-first approach to neighborhood communication.

We take user privacy, data protection, and responsible handling of location-related information seriously. Security vulnerabilities that could expose private community information or compromise user privacy are treated as important issues.

## Acknowledgments

We appreciate responsible security researchers and community members who help improve NearGrid.

Thank you for helping make NearGrid a safer platform for everyone.
